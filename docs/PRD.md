## 1. 产品概述

### 1.1 定位

**知策 QuantSage —— 前视偏差为零的 AI 投研 Agent：多 Agent 并行取证、PIT 约束语义检索、结论可回测验证。**

- 「MCP + 金融新闻 RAG + 回测」三者打通的开源项目目前不存在
- `available_at` PIT 约束：回测到第 T 天时，Agent 只能检索 `available_at <= T` 的新闻，杜绝前视偏差
- 核心证据：同一策略「允许未来信息 vs PIT 约束」各跑一次，量化两口径差异（PIT 保证回测不偷看未来；差异的方向不预设，如实呈现）

### 1.2 目标用户与核心场景

| 用户 | 诉求 |
|---|---|
| 面试官（demo 场景） | 10 分钟内看懂：Agent 能力、PIT 护城河、回测严谨性、工程素养 |
| 你自己（简历素材） | 每个阶段留下可量化、可展示的证据 |
| 泛化用户（个人投资者/投研学习者） | 独立完成「写策略 → 回测 → 模拟 → 复盘」 |

| 场景 | 路径 | 出口 |
|---|---|---|
| A 问行情/查新闻 | 快路径：RAG 直通 | 流式回答 + 来源标注 |
| B 深度研究 | 深路径：并行取证 → 辩论 → 综合 → 风控 → HITL | 可分享研报页 |
| C 策略验证 | 写策略 → 回测 → 前视偏差对比 → 模拟盘 | 绩效报告 |

### 1.3 阶段总览

| 阶段 | 代号 | 重心 | 目标 | 出口标准（DoD） |
|---|---|---|---|---|
| 一 | P1-Tn | Test | 跑通 demo | 量化闭环 + Agent 闭环双通，简历可演示 |
| 二 | P2-Mn | MVP | 产品最小可行化 | 注册用户可独立完成「写策略→回测→模拟→复盘」 |
| 三 | P3-En | Enterprise | 引入企业级思维（不追求企业级规模） | 可靠性/风控/工程化达标，故障注入通过 |
| 四（可选） | P4-Sn | Scale | 单机工程化（S1–S6）+ 后续愿景 | S1–S6 有 before/after 证据；后续愿景仍不排期 |

## 2. 功能清单

### 2.1 P1-Tn · 跑通 demo

> 目标：跑通「数据 → 策略 → 回测 → 结果」与「对话 → 工具 → 回答」两个最小闭环。

#### T1 地基

- uv 管理 Python 3.12，monorepo：`backend/` + `frontend/`
- Docker Compose：PostgreSQL 18、Redis、Qdrant
- 小石 CLI 装入独立 Python venv；MCP 以本地 stdio 接入
- 密钥只读 `.env`，不回显、不入库

**验收**：`docker compose up` 全绿；MCP 完成 initialize + tools/list + 一次有界认证查询。

#### T2 样例数据

- 小石 CLI 下载 3–5 个代表性标的日线历史（Parquet），DuckDB 直读
- 新闻事件样例数据（小批量），保留完整字段：`event_time` / `available_at` / `factor_scores` / `direction` / `stocks`

**验收**：DuckDB SQL 可查任意标的日线；事件样例 `available_at` 无空值且语义正确。

#### T3 Agent 对话

- FastAPI + LangGraph 单 Agent，模型用 `deepseek-flash` 快档
- 工具：行情查询（DuckDB）、新闻查询（小石 MCP）
- SSE 流式输出，前端可见中间工具调用步骤；Langfuse 记录完整 trace

**验收**：问「贵州茅台最近行情」，Agent 自主调工具并流式作答，Langfuse 有完整 trace。

#### T4 最小回测

- 事件驱动回测骨架：Bar 事件循环、简单撮合、手续费 + 滑点（可开关）
- 示例策略 ×2：①双均线；②事件驱动策略雏形（事件表规则过滤，不做语义检索）

**验收**：两个策略均可跑出完整结果；开关手续费/滑点结果有可见差异。

#### T5 分析输出

- 净值曲线、交易明细表、基础指标：总收益/年化/最大回撤/夏普/胜率
- 前视偏差对比：策略②在「允许未来信息」与「PIT 约束」下各跑一次

**验收**：对比报告能量化两口径差异（方向不预设）。

#### T6 极简前端

- Next.js 15：对话页（SSE 流式 + 工具步骤可视化）+ 回测结果页（TradingView Lightweight Charts + ECharts）
- 动手前先出 design brief（见第 5 节）

**验收**：浏览器内可完成一次对话和一次回测查看。

#### T7 示例策略教程

- 2 个示例策略的说明文档：策略逻辑、参数含义、结果解读

**验收**：新用户照文档可复现回测结果。

### 2.2 P2-Mn · MVP

> 目标：注册用户可独立完成「写策略 → 回测 → 模拟 → 复盘」。

#### M1 用户系统

- 注册/登录（邮箱+密码，JWT）；个人空间：会话历史、我的策略、我的回测
- 用户数据隔离；会话/策略/回测全量按用户归属过滤（P1 遗留阻塞项：会话列表无归属校验）
- 自选股 + 分组：加自选、分组管理、加自选以来涨幅

**验收**：注册→登录→各用户数据互不可见（含会话列表归属过滤）；刷新后会话可恢复；自选股增删分组后涨幅显示正确。

#### M2 数据层

- 行情扩到数据源覆盖的全市场日线；多周期以数据源实际覆盖为准
- 新闻日增量 ETL：每日定时拉取、去重（`content_hash`）、入库
- 92 天全量回填；长历史仅靠日增量积累（归档同受约 3 个月窗口限制，已证伪）
- 退市股覆盖确认（生存者偏差核实，§6 待确认③）
- 交易日历：ETL 与回测撮合依赖，来源以开源 A 股日历库为准并抽查核实
- 数据质量体检（脚本级）：缺失值 / 异常步长 / `available_at` 倒挂检测，日增量 ETL 的正确性护栏（完整版快照/看板留 P3-E3）

**验收**：ETL 连续运行 3 天无重复、无漏拉；全市场日线 DuckDB 秒级查询；注入脏数据时体检脚本报警。

#### M3 RAG 完整化

- 语料 ETL → BGE-M3 嵌入（批处理断点续跑）→ Qdrant 双索引（dense + sparse）
- 检索管线：元数据硬过滤（`available_at <= as_of` / 行业 / 标的 / 重要度）→ 并行稠密∥稀疏 → 服务端 RRF → rerank 精排 → top-3~5
- 分块：文档级 + 元数据 header 拼接；长文本才走 small-to-big
- 自建 200 条中文财经评测集，覆盖事实型/事件型/数值型/时间型/多跳型五类

**验收**：评测集 NDCG@10 达基线；`as_of` 参数下检索结果严格不含该时点之后的事件（PIT 单元测试）。

#### M4 策略工作台

- 在线编辑器（Monaco）+ Python 策略执行沙箱（子进程 + 资源配额）
- 参数配置；模板库（3–5 个内置策略）
- 策略代码前视泄漏静态检查（AST）：拦截 `shift(-n)` / `bfill` 等未来函数与未来索引，报错带行号——「前视偏差为零」从数据层延伸到用户策略代码层

**验收**：用户可在线编写策略并成功回测，坏代码不会拖垮服务；注入含未来函数的策略被检查器拦截并提示行号。

#### M5 回测增强

- 批量回测（多策略/多标的）；网格参数优化；基准对比（沪深 300/中证 500）
- A 股交易规则内建：T+1、涨跌停（一字板不可成交）、ST 规则、最小手数、停牌不可成交、印花税；信号按 next_open 成交
- 过拟合检验最小集：Deflated Sharpe + 网格最优 vs 全网格分布可视化
- 因子分析最小套件：新闻信号因子的 IC / 分层收益 / 多空价差 tear sheet（复用回测引擎，轻量自研）

**验收**：参数网格任务跑通；策略曲线可与基准叠加对比；一字涨停日买单被拒；因子分析报告与 Deflated Sharpe 检验生成。

#### M6 模拟盘

- 纸上交易：模拟账户（初始资金）、按日线信号撮合、持仓/订单管理、每日结算
- 费用/滑点/结算模型：佣金、印花税、滑点与回测同口径，每日按收盘价结算净值
- 决策审批闸门：下单前展示即将执行的决策（标的/方向/数量/理由），确认后才成交

**验收**：策略信号 → 模拟成交 → 持仓变化，全链路可查；费用扣减与手工样例一致。

#### M7 绩效分析

- 研报页：可分享独立 URL；简单归因（行业/因子）；风险指标
- 决策记忆 + 到期结算反思：决策到期按真实价格结算收益与相对基准 alpha，反思摘要写回长期记忆（复用 checkpointer/Store）
- 证据追溯面板：研报结论 → 来源回链（`source` / `original_source` / `content_hash` / `available_at` 时间线）
- 研报导出（Markdown/PDF）+ 版本快照（快照 hash + 数据快照版本，同一时点重放结论一致）
- 研报页脚含免责声明：「研究用途，不构成投资建议」

**验收**：分享链接在未登录浏览器可打开完整研报；决策到期自动结算并生成反思；导出 PDF 含证据链；同一数据快照下重放结论一致。

#### M8 深度研报多 Agent

- 意图路由：快路径（RAG 直通）⇄ 深路径（多 Agent）
- 深路径拓扑：并行取证 fan-out（行情技术面/新闻事件/基本面/因子，节点内 try/except）→ 证据归并 → Bull⇄Bear 辩论（≤3 轮硬上限）→ 单点综合撰写 → 代码化风控闸门 → 超限时 interrupt() 人工审批
- 取证角色 A 股化：政策面（小石政策语料）；基本面角色改为「PIT 基本面事件」——解读带 `available_at` 的公告事件（财报/业绩预告等 announcement 语料），不引入无 PIT 语义的第二数据源
- Agent 执行过程可视化：阶段环、并行瀑布、节点耗时、token/成本（与 Langfuse trace 一致）
- 双档模型：取证/路由用 `deepseek-flash`，辩论/综合用 `deepseek-v4-pro`
- 决策数据带来源标注（`source` / `original_source` / `content_hash`），做进 UI

**验收**：完整研报生成；辩论严格 ≤3 轮；token 成本在预算内；拔掉任一数据源，系统降级而非崩溃；基本面结论均源自带 `available_at` 的公告事件；过程可视化与 Langfuse trace 一致。

#### M9 轻量教学

- 使用教程 + 示例策略文档 + 常见问题

**验收**：文档覆盖全部核心流程，新用户可独立走通。

#### M10 研究首页

- 大盘总览：指数行情、涨跌家数、涨跌停家数、成交额、行业/概念板块热力图（全部日线数据派生）
- 事件日历/快讯流：按日事件流，每条并列 `event_time` 与 `available_at`（PIT 语义展示位），重要度排序，来源标注可展开
- **事件详情（M10d）**：点开任一条快讯（或个股页事件时间线上的事件），右侧抽屉给出这一条的**完整证据链**——正文全文、原文外链、**每只标的的打标理由**、人物、方向与因子分解、以及**平台的修订史**（版本 / 修订时刻 / 是否被改过）。口径：**照原样显示**，空值给「—」不编造

**验收**：大盘总览与日线数据抽查一致；事件日历点击任意事件可见来源三元组与双时间戳；**M10d 的抽屉七组齐全、修订字段与库里逐字一致、`source_url` 为空时不出链接**。

### 2.3 P3-En · 企业级思维

> 目标：按企业级标准补工程化、风控与协作方式，不引入企业级规模（单机可跑）。

#### E1 架构分层

- 定向抽接缝（数据源访问、LLM 网关两个横切点——E4 故障注入的注入面），不做全量分层重构；异步回测任务队列（DB 任务表 + 进程内队列 + 单 worker，不引 Celery/Redis Streams）；API 版本化（`/api/v1`，P2 已落地）

**验收**：回测异步执行，前端通过轮询/SSE 获取结果。

#### E2 多用户治理

- RBAC 简版（admin/user；admin = 审计与配额视图 **+ 平台运维端点**（ETL 触发与状态），不做管理后台）；资源隔离（P2 已落地）；配额管理（**在飞任务数上限**、**每日 Agent 请求数上限**——口径订正见 SPEC §3.0）

**验收**：用户 A 无法访问用户 B 数据；超配额被拒并给出明确提示。

#### E3 数据工程

- 数据质量校验完整版（缺失/异常/`available_at` 倒挂检测 + 告警与看板——M2 脚本级体检的升级）；数据版本（**快照 = 清单归档**，回滚 = 按清单从本地内容寻址对象库重物化——行情分片是**按年 × 复权**，不借「按日分片」）；热点查询 Redis 缓存（**跨请求**；可降级：挂了绕行直读；**单次运行内的重复读走进程内记忆**，不进 Redis）
- 告警渠道 = 看板红灯 + **体检结果结构化落档**（`health_runs.jsonl`；§4 已明确不做 IM 推送）；数据覆盖/质量看板：**标的覆盖摘要 + 下钻**（全市场 5,798 只逐只铺开在看板上不成立）、更新时间、异常告警一览
- **源侧发布停滞告警**：量「源侧自己多久没动」，与「本地 vs 源侧」（X5）分开判——源侧冻结时旧口径看不出是谁的锅

**验收**：注入脏数据触发告警；可回滚到上一数据快照。

#### E4 可靠性 L0–L7

- L0 限流（进程内令牌桶）；L1 LiteLLM 网关（配额/fallback/429 切换）；L2 LangGraph RetryPolicy + TimeoutPolicy；L3 模型降级链（pro⇄flash）；L4 熔断器（进程内状态）；L5 降级（部分结果 + 明确告知）；L6 护栏（步数/token/时间/成本硬上限）；L7 幂等键
- 限流/熔断状态不依赖 Redis——关键路径不绑外部组件，Redis 仅承担可降级的缓存角色
- 重试与熔断共用统一 policy 对象（dataclass 级，共享状态与预算，不做插件框架）
- 故障注入双轨：pytest 确定性注入（进 CI）+ 手动演练脚本（真拔数据源/杀 LLM，日志留档作验收证据）

**验收**：故障注入测试全部通过（拔数据源/杀 LLM/触发限流/熔断后恢复）。

#### E5 风控

- 仓位限制、止损、集中度、回撤控制——全部纯代码实现，LLM 不可改写；挂 M6 模拟盘持仓与下单路径（与 M6 审批闸门叠加）

**验收**：越限策略被闸门拦截；拦截与放行均有决策日志可审计。

#### E7 工程化

- 策略版本管理（DB 内版本记录 + diff 查看 + 可回滚，非真 Git 仓库）；CI/CD（GitHub Actions）；pytest 覆盖率门槛；后端 lint（ruff）；结构化日志 + 监控；决策审计日志（与 E5 共用一张表）
- 供应链审计进 CI：pip-audit / npm audit
- 实验可复现：每次回测绑定配置 + 数据快照版本（**随机种子已订正删除**：回测引擎纯确定性，全仓唯一随机数是重试抖动，不影响结果）
- Langfuse 可观测：每条 trace 记全模型+版本+prompt hash+工具序列+token 成本+延迟+用户
- 评估 CI gate：确定性断言（PIT 单测/覆盖率）进 CI；评测集的 **NDCG@10 读数不进 CI**（需真 Qdrant 索引 + BGE-M3 与真实 `data/`，GitHub runner 结构不可达）——进 CI 的是**指标公式与离线管线用例**，读数沿 `build_rag_eval.py` 手动轨；LLM-as-judge（DeepEval/RAGAS）手动触发（workflow_dispatch），不进每次 push

**验收**：CI 含确定性 eval gate（LLM-judge 手动档）；pytest 全绿且覆盖率达标；Langfuse 可回溯任意一次历史请求。

#### E8 安全

- 加固清单（库直用形态，2026-10-13 修订）：Postgres checkpointer（P2 已落地）；checkpoint 系列包显式 pin；JWT 过期/刷新策略；CORS 与安全响应头；依赖审计（pip-audit/npm audit，落地在 E7 CI）
- 注入防护；对外 MCP Server（FastMCP：暴露「新闻 PIT 检索」工具，自定返回上限）

**验收**：Claude Desktop 能调我们的 MCP 完成一次 PIT 检索；安全清单逐项核验。

#### E9 企业级文档

- 架构设计文档、风控专题、代码评审记录、事故复盘模板

**验收**：文档与实现一致，可直接作为简历/面试素材引用。

### 2.4 P4-Sn · 单机工程化与愿景

#### P4-Sn 单机工程化（S1–S6，已交付，2026-10-29）

**定位**：本轮 S1–S6 不是“真实流量触发”的后续愿景，而是用 P4-S0 基线数据做一次单机工程化演练：先修瓶颈、再补可靠性、最后验证多进程。完成后对外只能说“**经过压测与故障演练验证的单机工程化方案**”，不得写“生产级高可用/SLA/多 AZ”。

**交付读数（S6 复验，2026-10-29）**：2w bars c=300 1,710 req/s / p95 280ms、`/health` 11,599 req/s；1w 864 / 5,784；SSE 5/10/20/50/80 并发 0 错误；8 行故障演练通过；备份 4.6GB、PG+Qdrant+data 恢复 36.3s。与 S5 的 p95 231ms 差异按系统负载噪声如实记录。

**S1–S6**（技术规格见 [P4-Sn SPEC](specs/P4-Sn.md)）：

| 工作包 | 内容 | 验收口径 |
|---|---|---|
| S1 | `/events` 有界查询结果缓存 + 查询边界（默认窗口 + limit + `truncated`） | c=50 p95 <500ms、吞吐 ≥150 req/s；不静默改变“全部事件”语义 |
| S2 | 队列 v2：`SKIP LOCKED` + 租约/心跳 + 有限次重排 + 结果幂等；Worker 单实例 | kill -9 后 60s 内重排；max_attempts=2；0 重复结果 |
| S3 | 单 RAG 推理进程 + 有界队列/超时/并发闸门；交互降级 RRF、研究有界排队 | 10 并发 rerank p95 ≤5s 或快速降级；0 MPS 崩溃；降级可见 |
