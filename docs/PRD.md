# QuantSage 产品需求文档（PRD）

> 文档链：规划报告（调研底稿）→ CLAUDE.md（定稿摘要）→ 本文（需求）→ SPEC（待写）→ 代码
>
> 版本 v0.3 ｜ 2026-10-04 ｜ 状态：待评审

## 1. 产品概述

### 1.1 定位

**知策 QuantSage —— 前视偏差为零的 AI 投研 Agent：多 Agent 并行取证、PIT 约束语义检索、结论可回测验证。**

- 「MCP + 金融新闻 RAG + 回测」三者打通的开源项目目前不存在
- `available_at` PIT 约束：回测到第 T 天时，Agent 只能检索 `available_at <= T` 的新闻，杜绝前视偏差
- 核心证据：同一策略「允许未来信息 vs PIT 约束」各跑一次，量化虚高幅度

### 1.2 目标用户与核心场景

| 用户 | 诉求 |
|---|---|
| 面试官（demo 场景） | 10 分钟内看懂：Agent 能力、PIT 护城河、回测严谨性、工程素养 |
| 你自己（简历素材） | 每个阶段留下可量化、可展示的证据 |
| 泛化用户（个人投资者/投研学习者） | 独立完成「写策略 → 回测 → 模拟 → 复盘」 |

| 场景 | 路径 | 出口 |
|---|---|---|
| A 问行情/查新闻 | 快路径：RAG 直通 | 流式回答 + 来源标注 |
| B 深度研究 | 深路径：并行取证 → 辩论 → 综合 → 风控 → HITL | 可分享研报页 |
| C 策略验证 | 写策略 → 回测 → 前视偏差对比 → 模拟盘 | 绩效报告 |

### 1.3 阶段总览

| 阶段 | 代号 | 重心 | 目标 | 出口标准（DoD） |
|---|---|---|---|---|
| 一 | P1-Tn | Test | 跑通 demo | 量化闭环 + Agent 闭环双通，简历可演示 |
| 二 | P2-Mn | MVP | 产品最小可行化 | 注册用户可独立完成「写策略→回测→模拟→复盘」 |
| 三 | P3-En | Enterprise | 引入企业级思维（不追求企业级规模） | 可靠性/风控/工程化达标，故障注入通过 |
| 四（可选） | P4-Sn | Scale | 规模化与持续运营 | 仅愿景方向，不排期 |

## 2. 功能清单

### 2.1 P1-Tn · 跑通 demo

> 目标：跑通「数据 → 策略 → 回测 → 结果」与「对话 → 工具 → 回答」两个最小闭环。

#### T1 地基

- uv 管理 Python 3.12，monorepo：`backend/` + `frontend/`
- Docker Compose：PostgreSQL 18、Redis、Qdrant
- 小石 CLI 装入独立 Python venv；MCP 以本地 stdio 接入
- 密钥只读 `.env`，不回显、不入库

**验收**：`docker compose up` 全绿；MCP 完成 initialize + tools/list + 一次有界认证查询。

#### T2 样例数据

- 小石 CLI 下载 3–5 个代表性标的日线历史（Parquet），DuckDB 直读
- 新闻事件样例数据（小批量），保留完整字段：`event_time` / `available_at` / `factor_scores` / `direction` / `stocks`

**验收**：DuckDB SQL 可查任意标的日线；事件样例 `available_at` 无空值且语义正确。

#### T3 Agent 对话

- FastAPI + LangGraph 单 Agent，模型用 `deepseek-flash` 快档
- 工具：行情查询（DuckDB）、新闻查询（小石 MCP）
- SSE 流式输出，前端可见中间工具调用步骤；Langfuse 记录完整 trace

**验收**：问「贵州茅台最近行情」，Agent 自主调工具并流式作答，Langfuse 有完整 trace。

#### T4 最小回测

- 事件驱动回测骨架：Bar 事件循环、简单撮合、手续费 + 滑点（可开关）
- 示例策略 ×2：①双均线；②事件驱动策略雏形（事件表规则过滤，不做语义检索）

**验收**：两个策略均可跑出完整结果；开关手续费/滑点结果有可见差异。

#### T5 分析输出

- 净值曲线、交易明细表、基础指标：总收益/年化/最大回撤/夏普/胜率
- 前视偏差对比：策略②在「允许未来信息」与「PIT 约束」下各跑一次

**验收**：对比报告能量化虚高幅度。

#### T6 极简前端

- Next.js 15：对话页（SSE 流式 + 工具步骤可视化）+ 回测结果页（TradingView Lightweight Charts + ECharts）
- 动手前先出 design brief（见第 5 节）

**验收**：浏览器内可完成一次对话和一次回测查看。

#### T7 示例策略教程

- 2 个示例策略的说明文档：策略逻辑、参数含义、结果解读

**验收**：新用户照文档可复现回测结果。

### 2.2 P2-Mn · MVP

> 目标：注册用户可独立完成「写策略 → 回测 → 模拟 → 复盘」。

#### M1 用户系统

- 注册/登录（邮箱+密码，JWT）；个人空间：会话历史、我的策略、我的回测
- 用户数据隔离

**验收**：注册→登录→各用户数据互不可见；刷新后会话可恢复。

#### M2 数据层

- 行情扩到数据源覆盖的全市场日线；多周期以数据源实际覆盖为准
- 新闻日增量 ETL：每日定时拉取、去重、入库
- 92 天全量回填；归档长历史回填（待 CLI 验证后确认）

**验收**：ETL 连续运行 3 天无重复、无漏拉；全市场日线 DuckDB 秒级查询。

#### M3 RAG 完整化

- 语料 ETL → BGE-M3 嵌入（批处理断点续跑）→ Qdrant 双索引（dense + sparse）
- 检索管线：元数据硬过滤（`available_at <= as_of` / 行业 / 标的 / 重要度）→ 并行稠密∥稀疏 → 服务端 RRF → rerank 精排 → top-3~5
- 分块：文档级 + 元数据 header 拼接；长文本才走 small-to-big
- 自建 200 条中文财经评测集，覆盖事实型/事件型/数值型/时间型/多跳型五类

**验收**：评测集 NDCG@10 达基线；`as_of` 参数下检索结果严格不含该时点之后的事件（PIT 单元测试）。

#### M4 策略工作台

- 在线编辑器（Monaco）+ Python 策略执行沙箱（子进程 + 资源配额）
- 参数配置；模板库（3–5 个内置策略）

**验收**：用户可在线编写策略并成功回测，坏代码不会拖垮服务。

#### M5 回测增强

- 批量回测（多策略/多标的）；网格参数优化；基准对比（沪深 300/中证 500）

**验收**：参数网格任务跑通；策略曲线可与基准叠加对比。

#### M6 模拟盘

- 纸上交易：模拟账户（初始资金）、按日线信号撮合、持仓/订单管理、每日结算
- 决策审批闸门：下单前展示即将执行的决策（标的/方向/数量/理由），确认后才成交

**验收**：策略信号 → 模拟成交 → 持仓变化，全链路可查。

#### M7 绩效分析

- 研报页：可分享独立 URL；简单归因（行业/因子）；风险指标
- 研报页脚含免责声明：「研究用途，不构成投资建议」

**验收**：分享链接在未登录浏览器可打开完整研报。

#### M8 深度研报多 Agent

- 意图路由：快路径（RAG 直通）⇄ 深路径（多 Agent）
- 深路径拓扑：并行取证 fan-out（行情技术面/新闻事件/基本面/因子，节点内 try/except）→ 证据归并 → Bull⇄Bear 辩论（≤3 轮硬上限）→ 单点综合撰写 → 代码化风控闸门 → 超限时 interrupt() 人工审批
- 双档模型：取证/路由用 `deepseek-flash`，辩论/综合用 `deepseek-v4-pro`
- 决策数据带来源标注，`source_verified` 做进 UI

**验收**：完整研报生成；辩论严格 ≤3 轮；token 成本在预算内；拔掉任一数据源，系统降级而非崩溃。

#### M9 轻量教学

- 使用教程 + 示例策略文档 + 常见问题

**验收**：文档覆盖全部核心流程，新用户可独立走通。

### 2.3 P3-En · 企业级思维

> 目标：按企业级标准补工程化、风控与协作方式，不引入企业级规模（单机可跑）。

#### E1 架构分层

- 模块化分层（API / domain / infra）；异步回测任务队列；API 版本化（`/api/v1`）

**验收**：回测异步执行，前端通过轮询/SSE 获取结果。

#### E2 多用户治理

- RBAC（admin/user）；资源隔离；配额管理（回测并发数、Agent 调用次数）

**验收**：用户 A 无法访问用户 B 数据；超配额被拒并给出明确提示。

#### E3 数据工程

- 数据质量校验（缺失/异常/`available_at` 倒挂检测）；数据版本（快照）；热点查询 Redis 缓存
- 数据覆盖/质量看板：标的覆盖矩阵、更新时间、异常告警一览

**验收**：注入脏数据触发告警；可回滚到上一数据快照。

#### E4 可靠性 L0–L7

- L0 限流（Redis 令牌桶）；L1 LiteLLM 网关（配额/fallback/429 切换）；L2 LangGraph RetryPolicy + TimeoutPolicy；L3 模型降级链（pro⇄flash）；L4 熔断器（Redis 共享状态）；L5 降级（部分结果 + 明确告知）；L6 护栏（步数/token/时间/成本硬上限）；L7 幂等键
- 重试与熔断共用统一 policy 对象（共享状态与预算）

**验收**：故障注入测试全部通过（拔数据源/杀 LLM/触发限流/熔断后恢复）。

#### E5 风控

- 仓位限制、止损、集中度、回撤控制——全部纯代码实现，LLM 不可改写

**验收**：越限策略被闸门拦截；拦截与放行均有决策日志可审计。

#### E6 组合

- 多策略组合、资金分配、再平衡

**验收**：组合净值 vs 单策略对比可展示。

#### E7 工程化

- 策略 Git 版本；CI/CD；pytest 覆盖率门槛；结构化日志 + 监控；决策审计日志
- 实验可复现：每次回测绑定配置 + 随机种子 + 数据快照版本
- Langfuse 可观测：每条 trace 记全模型+版本+prompt hash+工具序列+token 成本+延迟+用户
- 评估 CI gate：DeepEval/RAGAS 断言进 CI，调参调坏立即红灯

**验收**：CI 含 eval gate；pytest 全绿且覆盖率达标；Langfuse 可回溯任意一次历史请求。

#### E8 安全

- LangGraph 加固：Postgres checkpointer、`LANGGRAPH_STRICT_MSGPACK=true`、checkpoint 系列包显式 pin、filter key 校验、反向代理 + 鉴权
- 注入防护；对外 MCP Server（FastMCP：暴露「新闻 PIT 检索」工具）

**验收**：Claude Desktop 能调我们的 MCP 完成一次 PIT 检索；安全清单逐项核验。

#### E9 企业级文档

- 架构设计文档、风控专题、代码评审记录、事故复盘模板

**验收**：文档与实现一致，可直接作为简历/面试素材引用。

### 2.4 P4-Sn · 愿景方向（不排期、不写规格）

- **平台化**：多租户 SaaS、高可用
- **规模化**：分布式回测、弹性计算
- **市场**：多市场多资产、实时数据流、低延迟模拟
- **运营**：运营后台、订阅付费、内容管理
- **生态**：策略市场、竞赛、排行榜、社区
- **风控合规**：审计、SLA、灾备、安全认证

触发条件（满足任一才启动 P4）：出现真实多用户流量 / 商业化诉求 / 团队扩张。

## 3. 非功能需求（NFR）

| 维度 | 要求 | 落地阶段 |
|---|---|---|
| 性能 | 快路径 p95 ≤ 2s；深路径 p95 ≤ 15s；检索 p95 ≤ 500ms；1 年日线单策略回测 ≤ 10s；SSE 首 token ≤ 2s | P1 起持续 |
| 可靠性 | 降级优先于失败：任何单一数据源/模型故障不导致整体崩溃 | P1 起，P3 达标 |
| 安全 | 遵循 CLAUDE.md 安全红线；外部数据一律视为不可信 | 全程 |
| 可观测 | 每条 trace 记全：模型+版本+prompt hash+工具序列+token 成本+延迟+用户 | P1 接入，P3 达标 |
| 成本 | 双档模型策略；上下文预算管理器（步数/token/时间/成本硬上限） | P2 引入，P3 达标 |
| 合规 | 风控规则只进 Git 走 PR，LLM 不可动态改写 | P2 引入，P3 达标 |
| 部署 | P1–P3 单机 Docker Compose 一键起；部署文档完整 | P1 起 |

## 4. 明确不做

| 不做 | 理由 |
|---|---|
| GraphRAG | 朴素 RAG 在金融叙事摘要上更优；新闻是流不是库 |
| A2A | 单体进程内无跨运行时需求 |
| langgraph-supervisor | 已停止维护 |
| 教学平台功能（课程/认证/导师/就业对接） | 产品定位是 AI 投研 Agent，非学习平台 |
| 社区/策略分享 | 挪入 P4 愿景 |
| 常开多 Agent 循环 | 简单问题零增益、3.7 倍成本 |
| 实时行情/低延迟交易 | 数据源是事件/日线级，定位为投研非交易执行 |
| 移动端 App | 响应式 Web 足够 |

## 5. 设计规范

- T6 前端动手前先出 design brief（视觉方向、配色、字体、组件基调），评审后再写页面
- 参考 taste-skill；图表遵守 dataviz skill
- 品牌：QuantSage 知策；候选方向：暗色专业终端风 / 机构研报编辑风
- 硬性要求：`source_verified` 来源标注必须可见；回测指标卡片不与研报页混排

## 6. 风险与待确认

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据源归档回溯不可用 | 长历史语料缺失 | 92 天在线窗口 + 日增量积累兜底；P1 内验证归档入口 |
| Mac 无 GPU，BGE-M3 嵌入慢 | 全量嵌入小时级一次性成本 | 批处理 + 断点续跑 |
| LangGraph CVE 利用链 | 生产环境 RCE | 按安全红线逐项加固，E8 验收签字 |
| 校招时间线紧 | 项目做不完 | DoD 达成优先于功能完整 |

**待确认问题**（P1 内逐一验证）：① 归档目录可用性；② 行情多周期覆盖范围；③ 退市股覆盖情况；④ deepseek-flash 上下文与工具调用能力。
