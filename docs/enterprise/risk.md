# 风控专题

> 读者：关心「这个系统怎么控制风险」的工程师、风控同学、面试官。
> 本文不重复 [E5 SPEC §6](../specs/P3-En.md) 的字段与端点，只回答三个问题：
> **怕什么、由谁强制、哪些不管**。
>
> 锚点用「文件 + 符号」；风控规则只进 Git，LLM 不可动态改写。

## 1. 风险全景

QuantSage 的风险不是一个「止损按钮」，而是五类风险、五种强制点。把它们放在一张表里，才能看出哪些是结构性的、哪些只是纵深防御的一层。

| 风险类 | 我们在怕什么 | 机制 | 强制点 | 不覆盖（如实） |
|---|---|---|---|---|
| **前视偏差** | 回测/研报偷看了当时还不知道的信息 | 双时间戳 + 回测设卡 + RAG 服务端过滤 + 策略 AST 检查 | `backtest/events.py`、`rag/retrieve.py`、`strategy/static_check.py` | 模型训练数据里的「记忆」；叙述层不可证 |
| **交易风险** | 单笔/总仓位失控、回撤扩大 | 四闸门：总仓位 / 单标的集中度 / 止损 / 回撤 | `paper/risk.py`（判据）、`paper/replay.py`（处置） | 盘中触发、组合优化、部分成交；止损按收盘判定、次日开盘成交，跳空可能更差 |
| **内容/合规** | LLM 编数字、越权下单、绕过人工审批 | 代码化风控闸门 + HITL + Agent 只到提案 + 报告 claim 闸门 | `agent/deep/risk_gate.py`、`paper/proposal.py`、`report/builder.py` | 叙述层的「听起来有据」；没有第三方合规认证 |
| **可靠性** | 单一数据源/模型故障拖垮整体 | policy 分类 / 重试 / 熔断 / 限流 / 降级 / 幂等 | `core/reliability.py`、`api/limits.py`、`api/idempotency.py` | 进程内单实例；Prometheus/Alertmanager 为 **S8 可选 profile**（默认不启动，6 条规则） |
| **安全** | 提示注入、用户代码逃逸、会话被续命 | 注入边界、沙箱、CSP、会话撤销、依赖审计 | `core/untrusted.py`、`strategy/isolation.py`、`core/session.py`、`frontend/lib/csp.ts` | 注入只做纵深防御；无第三方渗透测试 |

一句话：**前视偏差是护城河，交易四闸门是产品能力，内容/合规是红线，可靠性/安全是工程底座**。四类都不能靠「模型自觉」。

## 2. 前视偏差

### 2.1 双时间戳是数据模型的第一性

| 字段 | 含义 | 谁在用 |
|---|---|---|
| `event_time` | 事件发生时间 | 非 PIT 口径；用于量化两口径差异 |
| `available_at` | 平台首次可得到的时间 | **PIT 口径**：回测设卡、RAG 过滤、深研报锁时点 |
| `observed_at` | 我们观察到的时间 | 审计与数据体检 |

PIT 不是查询参数，而是结构：

1. **回测引擎**：`EventView.stamp()` 按 `Mode` 取 `available_at` 或 `event_time`；PIT 模式下 15:00 之后才可得的消息顺延到下一交易日
2. **RAG**：`available_at <= as_of` 写进 Qdrant **服务端 filter**，不是取回后再本地过滤
3. **策略代码**：运行前过 AST 静态检查（R0–R5），拦 `shift(-n)` / `bfill` 等未来函数
4. **深研报**：锁 `as_of`，证据必须满足 `available_at <= as_of`

### 2.2 两口径差异：方向不预设

T5 的实测是 **非 PIT 相对 PIT 的期末权益差异 −0.68% / −4.08% / 0.00%**（三标的样本快照）。方向可正可负——两模式信息集相同、只差时点，「更早入场」不等于更高收益。

所以对外表述只有一句：**PIT 约束保证回测不偷看未来**，不是「偷看未来一定赚更多」。后者被自家数据推翻。

### 2.3 不覆盖

- 模型训练数据里「记得」某段行情：这不是检索/回测能管的；深研报的叙述层没有对策，数字层靠代码取数与追溯闸门
- 语料本身的错误/缺失：数据体检能发现缺口与异常，但不能保证源侧内容正确

## 3. 交易风控：四个闸门

判据在 `paper/risk.py`，全部是**纯函数**：不读库、不调模型、不写状态。处置只在 `paper/replay.py`。

| 闸门 | 判据 | 处置 | 关键取舍 |
|---|---|---|---|
| **总仓位** | `(MV + N + 当日待成交买入) / E > max_gross_exposure` | 缩量到不越线；不足一手 → 拦截 | 策略只给方向，股数由系统算，所以「缩量」才有意义 |
| **单标的集中度** | `(P_i + N) / E > max_position` | 同上 | 单标的上限在 5 只以上池子里通常不触发 |
| **止损** | `(成本 − 市值) / 成本 ≥ stop_loss` | 生成 `approved` 风控卖出（`origin=risk`），**自动批准且不可驳回** | 按收盘价判定、次日开盘成交；跳空可能成交在更差价位 |
| **回撤** | `(峰值 − E) / 峰值 ≥ max_drawdown` | **只禁新开仓**；恢复到阈值下自动解禁 | 不强制平仓——避免在低点把仓位打光 |

另外两个硬拦截条件（与「买多少」无关）：

- **已持仓不加仓**（`position_open`）
- **止损挂单中**（`stop_loss_pending`）

### 3.1 顺序与幂等

一天的顺序与回测引擎同构（**风控段在估值之后、策略信号之前**）：

1. 开盘：成交上一交易日挂下、状态为 `approved` 的决策；仍 `pending` 的 → `expired`
2. 收盘：按收盘价估值，追加净值点
3. 风控：止损触发 → 回撤状态判定与审计（判据在 `paper/risk.py`，处置在 `paper/replay.py`）
4. 收盘后：推进事件可见性（PIT 闸门）→ 问策略要信号 → 生成下一批决策

`replay()` 是纯函数：同一份输入必得同一个账户状态。这是「推进」可幂等、可对账、可测试的依据，也是用户策略能跨 HTTP 请求保留状态的原因——只有「从会话起点重放」能让它看到同一串 bar。

### 3.2 审计

每次处置写 `decision_audit`（`paper/store.py`）：放行 / 缩量 / 拦截 / 触发，带判据与读数。被拦截的提案不在决策日志里，所以**审计表是生成期事实的权威记录**，不是决策日志的派生视图。

## 4. 内容与合规

### 4.1 三条不可协商的红线

1. **风控规则只进 Git**，LLM 不可动态改写
2. **风控闸门与校验用纯 Python**，LLM 不可决定合规
3. **`user_id` 只从请求上下文取**，绝不作 LLM 参数

### 4.2 深路径：代码化风控闸门 + HITL

`agent/deep/graph.py` 的 `risk_gate` 是纯 Python：

- 三类检查：① **正文数字无来源** → 回综合重写一次；仍不过 → 降级标注；② **绝对化 / 买卖指令表述** → `interrupt()` 交人；③ **预算超限**（调用数 / token / 时间 / 成本）→ `interrupt()` 交人
- 检查顺序固定：**预算 → 措辞 → 数字**——已经没钱了，再去重写或去问措辞都是错的决定顺序
- 从不抛异常、从不调用模型；重写只给一次（`rewrite_used` 进状态），第二次判到同一问题就降级，不无限重写

### 4.3 Agent 下单只到提案

`paper/proposal.py` 的边界写死在工具层：

- Agent 只能创建**当前 `as_of` 日、`pending`、`origin=agent`** 的模拟盘决策
- 不能批准 / 成交 / 改数量 / 改风控
- 用户必须逐条裁决；有待审批 Agent 提案时，「跑到结束」（`approve="all"`）直接 **409**
- 只支持会话池内标的、等额配额买入 / 全仓卖出；不做盘中触发

这条边界的产品含义：**Agent 是研究员，不是交易员**。

### 4.4 报告 claim 闸门

`report/builder.py::validate_claims` 钉死三件事，不过不落库：

1. `kind="fact"` 的块必须自证：要么带 `numbers`（值必须对得上，可复算），要么带 `evidence`（引用存在的键）
2. 证据键必须在 `body["evidence"]` 里真的存在（悬空引用 = 拒收）
3. `kind="inference"` 的块只承载模型正文，**不得携带 `numbers`**——推断不能冒充事实

这道闸门只管数字，不管叙述。叙述层的「听起来有据」是已知边界，不假装修好了。

## 5. 可靠性与安全

### 5.1 可靠性：降级优先于失败

| 层 | 机制 | 关键口径 |
|---|---|---|
| 错误分类 | `core/reliability.py::classify` | 只看异常结构（`status_code` / `retry_after`），不 import 上游 SDK |
| 重试 | `guard()` | 只重试可重试错误；429 按 `Retry-After` 停，且**立即开路、不参与失败计数** |
| 熔断 | 每依赖一份状态机 | 进程内单例；重启清零；冷却后半开探测 |
| 限流 | `api/limits.py` | 进程内令牌桶；429 带 `Retry-After`；SSE 在开流前拒 |
| 幂等 | `api/idempotency.py` | L7 幂等键；重复提交返回同一结果 |
| 降级 | 节点内 try/except | 深路径任一数据源失败只翻成 `errors`，不拖垮整跑 |

**红线**：关键路径不绑 Redis；熔断/限流不落盘、不依赖外部组件。缓存层任何异常都不得让请求失败。

### 5.2 安全：纵深防御

| 面 | 机制 | 不覆盖 |
|---|---|---|
| 提示注入 | `core/untrusted.py::wrap_untrusted`：外部文本包块、转义分隔标签 | 不是「解决了注入」；真正的闸门是角色不持工具 + 数字闸门 + 无副作用路径 |
| 用户代码 | 子进程 + CPU/墙钟/内存/stdout 四配额 + OS 级隔离（sandbox-exec / bwrap） | 完整容器化暂缓；残留风险是 API 与策略同宿主 |
| 未来函数 | AST 静态检查 R0–R5 | 静态检查不是定理证明；运行期仍靠沙箱 |
| 会话 | 滑动续期 + `token_version` 撤销 + `httpOnly` cookie | 撤销粒度按用户，不按设备 |
| 前端 | CSP nonce + `strict-dynamic`；`X-Content-Type-Options` 等 | 未捕获 500 不带安全头（已知例外） |
| 依赖 | `pip-audit` / `pnpm audit` 进 CI | 上游无补丁的传递依赖如实记录 |

## 6. 审计与可解释性

- **决策审计**：`decision_audit` 记录每次放行/缩量/拦截/触发，界面可逐条查
- **证据回链**：研报正文每个数字可点开追溯到来源事件（`content_hash` / `source` / `original_source`）
- **LLM trace**：Langfuse 记模型+版本+prompt hash+工具序列+token 成本+延迟+用户
- **数据指纹**：回测报告带 `data_digest`，同参重跑同指纹

## 7. 已知边界（如实）

1. **止损按收盘价判定、次日开盘成交**：跳空时成交价可能比止损价更差；不做盘中触发
2. **回撤只禁新开仓**：不强制平仓，回撤可能在极端行情下继续扩大
3. **模拟盘是单账户多标的等额配额**：不是组合优化；风控开启后不再与回测逐笔平价
4. **Agent 只到提案**：不能批准/成交/改风控；用户必须逐条裁决
5. **报告闸门只管数字**：叙述层可能「听起来有据」但并非从材料推出
6. **提示注入只做纵深防御**：边界标记是其中一层，不是安全证明
7. **无第三方渗透测试 / 合规认证**：这是一份工程自证，不是审计报告

## 8. 面试可讲的三个取舍

1. **止损为什么自动批准且不可驳回**：止损是风控动作，不是交易建议；把它交给人审批，会在最需要执行的时候引入犹豫。代价是可能被「假止损」洗出去——所以按收盘判定、次日开盘成交，不用盘中噪声触发。
2. **回撤为什么只禁新开仓、不强制平仓**：强制平仓会在低点把仓位打光，且与「止损」职责重叠。回撤闸门的目标是「停止加风险」，不是「清仓」。
3. **仓位/集中度为什么先缩量、不足一手才拦截**：策略只给方向，股数由系统按预算算；直接拦截会让「想买但超一点」变成「完全不买」，缩量更符合「上限是硬顶不是目标」的语义。
