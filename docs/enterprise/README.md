# 企业级文档

> 这组文档回答一个问题：**这个项目为什么能被称为「企业级」，而不是「功能多」**。
> 四篇各管一段，互相引用但不重复；技术契约以 [P3 SPEC](../specs/P3-En.md) 与代码为准。

## 30 秒导读

QuantSage 是一个**前视偏差为零**的 AI 投研 Agent。三条最值得先看的结论：

1. **PIT 是数据模型的第一性**：每条事件带 `event_time` 与 `available_at`，回测、检索、深研报都按后者设卡；两口径差异可量化，方向不预设。
2. **合规不在模型手里**：深路径的风控闸门是纯 Python；Agent 下单只到提案，人逐条裁决；风控规则只进 Git。
3. **单机形态是刻意选择**：`tasks` 表即队列、单进程内按 kind 的 worker 池（backtest×3 + grid/batch 各 1）、后台主实例锁；不引消息队列、暂缓全量容器化，触发条件写清楚。

## 事实口径

- **易变数字是快照**：测试数、覆盖率、延迟读数只在标注的日期成立；正文尽量链 SPEC，不写裸值。
- **文档不是第二事实源**：与 SPEC/代码冲突时，以 SPEC 与代码为准。
- **证据不在仓库里**：`logs/` 与 `docs/private/` 不入 Git；本文把关键事实写在正文，不依赖读者能打开证据目录。
- **不写没有证据的「企业级」**：每条结论要么有代码锚点，要么有 SPEC 节号，要么有实测读数。

## 维护约定

- 新增/修改这组文档时，把文件加进 `backend/scripts/check_docs.py` 的 `DOCS`，跑一次三检。
- 结构性断言用「文件 + 符号」锚点，不用行号；行号会随重构漂移。
- 不改 README 的门面定位：这组文档是「展开阅读」，README 仍是入口。
