> 旁人回填到的窗口起点通常晚于本文，跑出的数字与本篇不同属正常——这是数据源的边界，不是复现失败。

## 1. 策略逻辑

**一句话**：利多事件触发买入，持有 N 个交易日后卖出——本项目 PIT 护城河的演示策略。

- **合格事件**：`direction_norm == "bullish"` **且** `factor_scores.score >= min_score`（默认 50）
  - `direction_norm` 是落盘时对原值归一的结果：原值中英混用（`利多` / `bullish` / `positive` / `看多` 均归为 `bullish`）；`高管人事` 这类没有方向语义的标签归 `NULL`，不臆造情感极性
- **买入**：合格事件出现即满仓买入（100 股整手，按可用现金校验，规则同双均线）
- **持有期**：成交日算第 1 天，满 `hold_days` 个交易日后在收盘出信号，次日开盘卖出；**持有期内忽略一切新利多**，不加仓、不续期
- **同日多条**：同一根 bar 上有多条合格事件时，取**按设卡时间与 `event_id` 排序的第一条**——不是评分最高的那条（实例见第 9 节）

代码：[`backend/app/backtest/strategies/event_driven.py`](../../backend/app/backtest/strategies/event_driven.py)（策略）、[`backend/app/backtest/events.py`](../../backend/app/backtest/events.py)（PIT 闸门）。

## 2. PIT 语义：三个时间戳与一条分界线

每条事件带三个时间戳：

| 字段 | 含义 |
|---|---|
| `event_time` | **事发**：新闻所讲事情发生的时刻 |
| `available_at` | **平台首次可用**：这条消息在数据源里第一次可被取到的时刻 |
| `observed_at` | 观察时刻（数据源标注） |

**分界线是每根 bar 的收盘时刻 15:00（Asia/Shanghai）**：

- **PIT 模式**按 `available_at` 设卡——15:00 之后才可得的消息，顺延到下一交易日才可见。回测跑到第 T 天时，只能看到当时真的能拿到的信息
- **非 PIT 模式**按 `event_time` 设卡——等同假设「事发即知」，是**故意穿越未来**的对照组，用来量化前视偏差有多大

两种模式的全部差别压缩在一行代码里（`EventView.stamp()`，定义在 `backend/app/backtest/types.py`），策略与撮合对此零感知——非 PIT 的「穿越未来」在策略层零改动。

> 行情数据不受这道闸门影响：日线 OHLC 按「当日收盘已知」处理。`bars.available_at` 是整表下载快照而非逐 bar 可得时间，对 bars 逐 bar 设卡会把历史全滤空。

## 3. 参数含义

| 参数 | 默认 | 含义 |
|---|---|---|
| `min_score` | 50 | 合格事件的最低评分（0~100） |
| `hold_days` | 5 | 买入后持有的交易日数 |

三处入口：CLI 的 `--min-score` / `--hold-days`；`POST /api/v1/backtest` 的 `params`；回测页表单的「最低评分 / 持有天数」。后端只校验键名不校验值，值域由调用方保证（回测页已有校验）。

## 4. 复现

```bash
cd backend
uv run python scripts/run_report.py --symbol 600519 --strategy event_driven
```

区间缺省：起点 = 该标的**最早一条事件的日期**（本次 2026-07-15），终点 = **最后一根 bar**（本次 2026-10-09）。默认 `--pit-mode both`：主指标跑 PIT，另附双模式对比。

## 5. 结果解读

指标口径与 [双均线一篇](ma_cross.md#4-结果解读) 完全一致（252 日年化、回撤取正值、夏普 ddof=1、胜率只算已平仓、基准为份额化买入持有）。事件驱动特有的两条：

- **期末持仓单列**：3 笔已平仓 1 胜 2 负（胜率 33.33%），第 4 次建仓的 +1.82% 浮盈不进胜率；报告必须单独给出，否则「胜率」会失真
- **样本只有 57 个交易日**：年化与夏普按 252 折算会放大噪声约 √(252/57) ≈ 2.1 倍。报告与回测页都常驻这条提示——短窗口的年化、夏普不要当结论用

读这一份：策略 +3.04%、基准 +0.88%，跑赢 2.16pp。但**别急着读成「事件驱动有效」**：3 笔平仓里 2 笔亏损，跑赢主要来自第 1 笔的 +3.61% 与期末未平仓那 800 股的浮盈——后者还没落袋。这是小样本的如实结果，不需要解释成策略有效或无效。

## 6. 前视偏差对比怎么读

同区间、同成本、同参数，**唯一差别是拿哪个时间戳设卡**。本次两口径**结果完全相同**：

| 指标 | PIT（`available_at`） | 非 PIT（`event_time`） | 差值 |
|---|---|---|---|
| 总收益 | +3.04% | +3.04% | +0.00pp |
| 年化 | +14.14% | +14.14% | +0.00pp |
| 最大回撤 | 3.86% | 3.86% | +0.00pp |
| 夏普 | +0.99 | +0.99 | +0.00 |
| 胜率 | 33.33% | 33.33% | +0.00pp |
| 交易次数 | 3 | 3 | 0 |
| 期末权益 | 1,030,361.78 | 1,030,361.78 | — |

**核心量化值** `delta.final_equity_pct` = **0.00%**。报告同时打印说明：非 PIT 确实用了当时尚不可得的信息（T4 的反向证明已验），只是**这个窗口里**这些信息没改变任何一次决策。

### 为什么这次没差：闸门是真的，只是这次没拦住东西

窗口内 600519 **合格事件共 16 条**（`bullish` 且 `score ≥ 50`），PIT 口径下的去向：

| 去向 | 条数 | 说明 |
|---|---|---|
| 触发入场 | 4 | 第 4 节表里的 3 笔 + 期末那笔未平仓 |
| 持有期内被忽略 | 11 | 信号当天已有持仓，不加仓、不续期 |
| 同日可见但排序靠后 | 1 | `news:2028988`（评分 82.489）与 `news:2025376`（52.774）同日可见，后者设卡时间更早故被取用 |

16 条里**两口径可见日不同的只有 1 条**：

| 事件 ID | 评分 | 事发 | 首次可用 | 滞后 | 非 PIT 可见 | PIT 可见 |
|---|---|---|---|---|---|---|
| `news:854409` | 64.187 | 07-28 11:09 | **07-28 20:36** | 9.5 小时 | 07-28 | **07-29** |

它的 `event_time` 在 15:00 收盘前、`available_at` 在收盘后，正好跨过那条分界线。但**在默认门槛下它没改变结果**：07-28 当天另有一条设卡更早的 `news:854503`（54.3），两口径都在 07-28 可见，于是都在 07-29 开盘买入；等 `news:854409` 在 PIT 下 07-29 才可见时，持仓已经建好了，它落进「持有期内被忽略」那一桶。

**这正是 PIT 闸门该有的样子**：它拦的是「当时还拿不到的信息」，而不是保证每次都拦出差异。要不要有差异，取决于某条事件是否恰好跨线、以及跨线的那条是否恰好是决策者。下面这一节给出「恰好是决策者」时的对照。

## 7. 参数与成本开关实证

### 把门槛抬到 60：同一条事件翻身成了决策者

```bash
uv run python scripts/run_report.py --symbol 600519 --strategy event_driven --min-score 60
```

| 指标 | min_score = 50（默认） | min_score = 60 |
|---|---|---|
| 总收益 | +3.04% | +0.71% |
| 年化 | +14.14% | +3.17% |
| 最大回撤 | 3.86% | 4.89% |
| 夏普 | +0.99 | +0.29 |
| 胜率 | 33.33% | 33.33% |
| 交易次数 | 3 | 3 |
| 期末权益 | 1,030,361.78 | 1,007,080.37 |
| 超额收益 | +2.16% | −0.17% |
| 期末持仓 | 800 股（浮盈 +1.82%） | 无（全部已平仓） |

要点：交易次数同为 3，但**成交的事件换了一批**——合格事件从 16 条降到 9 条。第 2 笔从 `news:854503`（54.3）换成 **`news:854409`（64.187）**，入场日随之从 07-29 推到 **07-30**；第 3 笔从 `news:2025376`（52.774）换成 `news:2028988`（82.489，同为 08-25 入场）。「提高门槛」不等于「交易更少」，它改变的是**哪些事件合格**，进而改变入场时点与持有区间。

**而这一换，就把第 6 节那条跨线事件换成了决策者**——两口径不再相同：

| 指标 | PIT（`available_at`） | 非 PIT（`event_time`） | 差值 |
|---|---|---|---|
| 总收益 | +0.71% | +1.23% | **+0.52pp** |
| 年化 | +3.17% | +5.57% | +2.40pp |
| 最大回撤 | 4.89% | 3.86% | −1.03pp |
| 期末权益 | 1,007,080.37 | 1,012,329.62 | 差 5,249.25 元 |

入场日序列是最直接的证据：

| | 第 1 次 | 第 2 次 | 第 3 次 |
|---|---|---|---|
| PIT | 07-16 | **07-30** | 08-25 |
| 非 PIT | 07-16 | **07-29** | 08-25 |

同一批事件、同一套规则，只有一次入场差了一天，期末权益就差出 5,249.25 元。

- **方向不预设**：本次非 PIT **更高**。前视偏差的收益方向取决于信号 alpha，**不恒为正**——早一天知道不等于赚更多。报告如实打印方向，不写「虚高」（T5 实测三标的时方向就有正有负）
- **同一个策略、同一个窗口，默认门槛下差值 0.00pp、抬到 60 就变成 +0.52pp**：这正说明「PIT 约束」的价值在于**保证回测没有偷看未来**，而不在于「不做约束就一定能多赚」

## 9. 易误读点

1. **同一根 bar 多条合格事件取排序第一条，不取最高分**：`news:2028988` 评分 82.489，却输给了同日可见更早、评分只有 52.774 的 `news:2025376`
2. **持有期内忽略新利多**：窗口里 11 条合格事件落空，全因当时已在持仓；策略不追高、不加仓、不续期
3. **`entry_dates` 是成交日，不是信号日**：信号在收盘生成、次日开盘成交，PIT 与非 PIT 的一天之差就来自这一层
4. **两口径差值可以是 0，且不需要解释成「闸门失效」**：默认门槛下本次就是 0.00pp。闸门只保证「看不到当时拿不到的信息」，不保证每次都拦出差异（第 6 节）
5. **`pit_mode=both` 时 `meta.mode` 恒为 `"pit"`**：主指标跑的就是 PIT，界面上别拿表单值当结论
6. **`meta.cutoff_field` 恒为 `available_at`**：它是事件游标的属性，与策略是否消费事件无关（双均线那份报告也有这个字段，见 [ma_cross](ma_cross.md#7-三个易误读点)）
7. **期末持仓不进胜率与交易次数**：本次那 800 股 +1.82% 的浮盈不计入 33.33% 的胜率
