# 事件驱动策略（event_driven）

> **读者**：已克隆本仓库、样例数据已落盘的读者（行情取数见 `backend/scripts/download_bars.py`，事件语料见 `backend/scripts/download_events.py`）。
>
> **本文数字来自一次真实回测**，照抄第 4 节的命令即可逐项对上。数据快照：`data/bars/600519.qfq.parquet`（424 根，sha256 前 12 位 `9654d7c55b63`）与 `data/events/600519.parquet`（88 条，事件窗口 2026-07-05 → 2026-09-30，sha256 前 12 位 `b1cf196031f7`；清单见 `data/_meta/{bars,events}.json`）。**换一份数据快照，数字会变，结构与读法不变。**

## 1. 策略逻辑

**一句话**：利多事件触发买入，持有 N 个交易日后卖出——本项目 PIT 护城河的演示策略。

- **合格事件**：`direction_norm == "bullish"` **且** `factor_scores.score >= min_score`（默认 50）
  - `direction_norm` 是落盘时对原值归一的结果：原值中英混用（`利多` / `bullish` / `positive` / `看多` 均归为 `bullish`）；`高管人事` 这类没有方向语义的标签归 `NULL`，不臆造情感极性
- **买入**：合格事件出现即满仓买入（100 股整手，按可用现金校验，规则同双均线）
- **持有期**：成交日算第 1 天，满 `hold_days` 个交易日后在收盘出信号，次日开盘卖出；**持有期内忽略一切新利多**，不加仓、不续期
- **同日多条**：同一根 bar 上有多条合格事件时，取**按设卡时间与 `event_id` 排序的第一条**——不是评分最高的那条（实例见第 6 节）

代码：[`backend/app/backtest/strategies/event_driven.py`](../../backend/app/backtest/strategies/event_driven.py)（策略）、[`backend/app/backtest/events.py`](../../backend/app/backtest/events.py)（PIT 闸门）。

## 2. PIT 语义：三个时间戳与一条分界线

每条事件带三个时间戳：

| 字段 | 含义 |
|---|---|
| `event_time` | **事发**：新闻所讲事情发生的时刻 |
| `available_at` | **平台首次可用**：这条消息在数据源里第一次可被取到的时刻 |
| `observed_at` | 观察时刻（数据源标注） |

**分界线是每根 bar 的收盘时刻 15:00（Asia/Shanghai）**：

- **PIT 模式**按 `available_at` 设卡——15:00 之后才可得的消息，顺延到下一交易日才可见。回测跑到第 T 天时，只能看到当时真的能拿到的信息
- **非 PIT 模式**按 `event_time` 设卡——等同假设「事发即知」，是**故意穿越未来**的对照组，用来量化前视偏差有多大

两种模式的全部差别压缩在一行代码里（`EventView.stamp()`），策略与撮合对此零感知——非 PIT 的「穿越未来」在策略层零改动。

> 行情数据不受这道闸门影响：日线 OHLC 按「当日收盘已知」处理。`bars.available_at` 是整表下载快照而非逐 bar 可得时间，对 bars 逐 bar 设卡会把历史全滤空。

## 3. 参数含义

| 参数 | 默认 | 含义 |
|---|---|---|
| `min_score` | 50 | 合格事件的最低评分（0~100） |
| `hold_days` | 5 | 买入后持有的交易日数 |

三处入口：CLI 的 `--min-score` / `--hold-days`；`POST /api/v1/backtest` 的 `params`；回测页表单的「最低评分 / 持有天数」。后端只校验键名不校验值，值域由调用方保证（回测页已有校验）。

## 5. 结果解读

指标口径与 [双均线一篇](ma_cross.md#4-结果解读) 完全一致（252 日年化、回撤取正值、夏普 ddof=1、胜率只算已平仓、基准为份额化买入持有）。事件驱动特有的两条：

- **期末持仓单列**：4 笔已平仓 1 胜 3 负（胜率 25%），第 5 次建仓的 +1.46% 浮盈不进胜率；报告必须单独给出，否则「胜率」会失真
- **样本只有 55 个交易日**：年化与夏普按 252 折算会放大噪声约 √(252/55) ≈ 2.1 倍。报告与回测页都常驻这条提示——短窗口的年化、夏普不要当结论用

读这一份：策略 −0.27%、基准 +0.53%，跑输 0.80pp；4 笔平仓里 3 笔亏损，说明**「利多事件 → 买入」在这个窗口里没有体现出超额**。这是小样本的如实结果，不需要解释成策略有效或无效。

## 6. 前视偏差对比怎么读

同区间、同成本、同参数，**唯一差别是拿哪个时间戳设卡**：

| 指标 | PIT（`available_at`） | 非 PIT（`event_time`） | 差值 |
|---|---|---|---|
| 总收益 | −0.27% | −0.95% | −0.68pp |
| 年化 | −1.22% | −4.27% | −3.05pp |
| 最大回撤 | 6.70% | 7.10% | +0.40pp |
| 夏普 | −0.01 | −0.22 | −0.21 |
| 胜率 | 25.00% | 25.00% | +0.00pp |
| 交易次数 | 4 | 4 | 0 |
| 期末权益 | 997,329.16 | 990,518.27 | — |

- **核心量化值**：`delta.final_equity_pct` = **−0.68%**（非 PIT 相对 PIT 的期末权益差异比例）。本次非 PIT **更低**——**前视偏差的收益方向取决于信号 alpha，不恒为正**，报告如实打印方向，不预设「虚高」
- **入场日序列**是差异最直接的证据：

  | | 第 1 次 | 第 2 次 | 第 3 次 | 第 4 次 | 第 5 次 |
  |---|---|---|---|---|---|
  | PIT | 07-16 | 07-29 | 08-25 | **09-08** | 09-30 |
  | 非 PIT | 07-16 | 07-29 | 08-25 | **09-07** | 09-30 |

  五次入场里只有第 4 次差一天，而期末权益就差出了 6,810.89 元（−0.68%）。

### 那一天差在哪：一条事件的溯源

| 事件 ID | 评分 | 事发 | 首次可用 | 滞后 | PIT 成交 | 非 PIT 成交 |
|---|---|---|---|---|---|---|
| `news:2210092` | 72.345 | 09-04 06:24 | **09-06 06:37** | 48.2 小时（跨周末） | **09-08** | **09-07** |

- 非 PIT 按 `event_time` 设卡：09-04（周五）06:24 早于当日 15:00 → **周五收盘即可见** → 周五收盘出信号 → 09-07（周一）开盘成交
- PIT 按 `available_at` 设卡：09-06（周日）06:37 才可用 → **周一收盘才可见** → 周一收盘出信号 → **周二开盘成交**
- 晚一天成交，价格不同，这笔交易的盈亏跟着变，并连锁影响第 5 次建仓的可用现金

### 其余四次为什么没差

五个触发的入场里只有一条分岔。分岔的条件是 `event_time` 与 `available_at` 落在**不同的「bar 收盘时刻」区间**：两者同在 15:00 前或同在 15:00 后都不分岔。

窗口内**合格事件共 18 条**（`bullish` 且 `score ≥ 50`），去向如下：

| 去向 | 条数 | 说明 |
|---|---|---|
| 触发入场 | 5 | 上表 |
| 持有期内被忽略 | 12 | 信号当天已有持仓，不加仓、不续期 |
| 同日可见但排序靠后 | 1 | `news:2028988`（评分 82.489，可见于 08-24）高于同日被取用的 `news:2025376`（52.774），但后者可见更早，故被取用 |

（18 条里两口径**可见日不同**的其实有 6 条，但它们要么落在持仓期、要么不改变入场决策，所以只有 1 条影响了结果。）

列出这 18 条：

```python
from app.data import duckdb_client
from app.backtest.events import parse_factor_score

rows = duckdb_client.events(symbol="600519")
qual = [r for r in rows
        if r["direction_norm"] == "bullish"
        and (s := parse_factor_score(r["factor_scores"])) is not None and s >= 50]
```

## 7. 参数与成本开关实证

**换 `min_score`**：

```bash
uv run python scripts/run_report.py --symbol 600519 --strategy event_driven --min-score 60
```

| 指标 | min_score = 50（默认） | min_score = 60 |
|---|---|---|
| 总收益 | −0.27% | −2.06% |
| 年化 | −1.22% | −9.11% |
| 最大回撤 | 6.70% | 7.72% |
| 夏普 | −0.01 | −0.58 |
| 胜率 | 25.00% | 25.00% |
| 交易次数 | 4 | 4 |
| 期末权益 | 997,329.16 | 979,367.76 |
| 期末持仓 | 700 股（浮盈 +1.46%） | 无 |

要点：交易次数同为 4，但**成交的事件换了一批**——门槛提高后，第 2 笔从 `news:854503`（54.3）换成 `news:854409`（64.187），第 3 笔从 `news:2025376`（52.774）换成 `news:2028988`（82.489），期末那笔 `news:2268818`（50.164）被挡下，故期末空仓。「提高门槛」不等于「交易更少」，它改变的是**哪些事件合格**，进而改变入场时点与持有区间（本组对照里 18 条合格事件降到 10 条）。

**换成本开关**：

```bash
uv run python scripts/run_report.py --symbol 600519 --strategy event_driven --no-costs
```

| 指标 | 默认（费用 + 滑点） | `--no-costs` |
|---|---|---|
| 总收益 | −0.27% | +0.72% |
| 期末权益 | 997,329.16 | 1,007,180.00 |

4 笔平仓 + 1 次建仓共 9 次成交，摩擦成本约 1.0pp——佣金万 2.5（单笔最低 5 元）、卖出印花税 0.05%、滑点 5bps，单次往返约 0.2%。`--no-fees` / `--no-slippage` 可分别只关其一。

## 9. 易误读点

1. **同一根 bar 多条合格事件取排序第一条，不取最高分**：`news:2028988` 评分 82.489，却输给了同日可见更早、评分只有 52.774 的 `news:2025376`
2. **持有期内忽略新利多**：窗口里 12 条合格事件落空，全因当时已在持仓；策略不追高、不加仓、不续期
3. **`entry_dates` 是成交日，不是信号日**：信号在收盘生成、次日开盘成交，PIT 与非 PIT 的一天之差就来自这一层
4. **`pit_mode=both` 时 `meta.mode` 恒为 `"pit"`**：主指标跑的就是 PIT，界面上别拿表单值当结论
5. **`meta.cutoff_field` 恒为 `available_at`**：它是事件游标的属性，与策略是否消费事件无关（双均线那份报告也有这个字段，见 [ma_cross](ma_cross.md#7-三个易误读点)）
6. **期末持仓不进胜率与交易次数**：本次那 700 股 +1.46% 的浮盈不计入 25% 的胜率
