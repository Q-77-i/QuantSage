## 1. 策略逻辑

**一句话**：MA5 上穿 MA20 全仓买入，下穿则全仓卖出；只看收盘价，信号次日开盘成交。

- **标的与口径**：贵州茅台 600519，日线，前复权（qfq）
- **交叉判定**：用「前一根 vs 当前根」的四个均值比较——`fast_prev <= slow_prev and fast_now > slow_now` 为金叉，反向为死叉。**只在穿越发生的那一根触发一次**，靠判定式本身保证，不靠状态记忆，因此同一段趋势内不会反复触发
- **成交时点**：信号在**当根收盘**生成，成交在**下一根开盘**——防止「用当根收盘价成交」这种日内前视
- **仓位**：满仓进、空仓出。买入按 100 股整手向下取整，并按「成交金额 + 费用 ≤ 可用现金」逐手校验（跳空高开也不打穿现金）；卖出一次清空，故不存在零股
- **不做**：加仓、做空、止损、仓位管理

代码：[`backend/app/backtest/strategies/ma_cross.py`](../../backend/app/backtest/strategies/ma_cross.py)（策略）、[`backend/app/backtest/broker.py`](../../backend/app/backtest/broker.py)（撮合与整手）。

## 2. 参数含义

| 参数 | 默认 | 含义 |
|---|---|---|
| `fast` | 5 | 快线窗口：最近 N 根收盘价的简单均值 |
| `slow` | 20 | 慢线窗口 |

三处入口：CLI 的 `--fast` / `--slow`；`POST /api/v1/backtest` 的 `params`；回测页表单的「快线 / 慢线」。

> ⚠ 后端只校验参数的**键名**（未知键返回 422），不校验值：`fast=20, slow=5` 会被照单全收，静默跑出无意义的交叉。回测页表单有值域校验（`fast ≥ 1`、`slow ≥ 2`、`fast < slow`）；直接打 API 时须自己保证。

## 4. 结果解读

### 指标口径

| 指标 | 口径 |
|---|---|
| 总收益 | 期末权益 / 初始资金 − 1 |
| 年化 | 按 252 交易日折算 |
| 最大回撤 | 净值自峰值回落的最大**幅度**（取正值） |
| 夏普 | rf = 0；日净值收益的样本标准差（ddof=1）年化；样本不足或标准差为 0 时显示 `—` |
| 胜率 / 交易次数 | **只统计已平仓交易** |
| 基准 | 同标的买入持有：首根收盘价**份额化**全额买入（不受 100 股整手限制），扣一次买入成本，持有到期末按收盘价估值（不卖出，故不计印花税） |

### 这一份怎么读

- 策略总收益 −10.02%，但基准（躺平持有）也是 −10.28%——**绝对收益为负 ≠ 跑输**。报告把两者并列，先看基准再看超额（本次 +0.26pp）
- 13 笔里 4 胜 9 负（胜率 30.77%），最大单笔盈利 +65,528.99（+7.77%）、最大单笔亏损 −42,718.40（−4.90%）：低胜率、盈亏比驱动的典型形态
- 股数在 600~700 之间浮动：每次按可用现金全额买入 + 整手取整，亏损之后可用现金变少，股数自然跟着变，不是固定金额下单
- 期末无持仓（全部已平仓），故 13 笔就是全部交易，胜率与交易次数不含未平仓

## 6. 在回测页上复现

打开 `http://localhost:3001/backtest`（后端 8000），按上表填：策略「双均线」、标的「600519 贵州茅台」、快线 5 / 慢线 20、起止日留空、成本与滑点保持默认、模式任意（双均线两种模式同结果）。

页面上会看到六块：指标卡（含样本量提示位）、净值曲线、K 线（标注买卖点，与交易明细逐条对应）、PIT 对比区、交易明细、事件表。其中 PIT 对比区显示一句话：

> 双均线不消费事件语料，两种模式必然得到同一份结果，因此不做无意义的二次回测。要看这个对比，请选事件驱动策略。

这不是报错，原因见下一节。

## 7. 三个易误读点

1. **没有 PIT 对比是正常的**：`pit_comparison` 为 `null`。PIT 闸门只作用于**事件语料**，双均线不读事件，两种模式必然同结果，跑第二遍只会误导
2. **报告头部的「按 available_at 设卡」对双均线是空转**：`meta.cutoff_field` 是事件游标的属性，与实际是否过滤事件无关。别据此以为双均线也做了 PIT 过滤
3. **期末持仓不进胜率与交易次数**：本次期末空仓不受影响；有持仓时报告会单列浮动盈亏——否则「胜率」会失真
