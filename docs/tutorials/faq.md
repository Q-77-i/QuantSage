# 常见问题（FAQ）

> **按症状查，不按功能查**——你是带着问题来的，不是来复习功能清单的。
> 每条写全三件事：**你看到什么** → **为什么** → **怎么办**。提示语都是界面或接口的**原文**，
> 可以直接对上你屏幕上那行字。
>
> 还没用过这个产品？先看 [使用教程](getting-started.md)。

## A. 账号与登录

### A1. 提示「密码不得超过 72 个字节」

**为什么**：密码哈希用的是 bcrypt，它只认前 72 个字节。为了不出现「密码对了却登不上」，我们在**入口就按字节拒绝**（不是按字符数）。

**怎么办**：换个短一点的密码。注意**一个汉字算 3 个字节**——24 个汉字就到上限了，`至少 8 位` 这个界面提示远不是全部规则。

### A2. 提示「邮箱格式不正确」/「密码至少 8 个字节」

**怎么办**：邮箱要能匹配基本的 `a@b.c` 形状；密码按 UTF-8 字节数算，最少 8 字节。注册页的「确认密码」不一致时会提示 `两次输入不一致`。

### A3. 刷新一下就被踢回登录页了

**为什么**：会话是 httpOnly cookie，有有效期。**一直在用就会自动续期**（过半程换一次新 cookie），所以常见原因是：**放了很久没动**（闲置满 7 天）、刚在别处**登出**过（登出会作废此前发出的所有会话）、或者在别的浏览器/无痕窗口里。

**怎么办**：重新登录即可，登录后会**回到你原来那一页**（地址栏带 `?next=`）。**你之前的数据一条都不会丢**——自选、回测、策略、模拟盘、研报都在账号下，与浏览器无关。

### A4. 提示「该邮箱已被注册」

**怎么办**：直接去登录页。忘了密码目前**没有自助重置**（已知边界），换一个邮箱注册，或联系部署这套服务的人。

## B. 回测：跑不出来

### B1. 报 400：「事件语料只覆盖 … 起（新闻源保留期 3 个月，更早的事件不可得），请求的起点 … 早于它」

**你看到什么**：完整提示是

> 事件语料只覆盖 2026-07-07 起（新闻源保留期 3 个月，更早的事件不可得），请求的起点 2020-01-02 早于它——把 start 改到 2026-07-07 之后；若要看更长的历史，请改用不消费事件的 ma_cross。

**为什么**：事件驱动策略要读事件，而**新闻源只保留 3 个月**（滚动窗口），更早的事件永久不可得——不是我们没下载，是上游没有了。

**怎么办**：三选一——把起点改到语料覆盖范围之内；**起点留空**（后端自动从语料起点开跑）；或换成**双均线**（它不需要事件语料，可以跑到 2020 年）。

### B2. 报 404：「… 在事件语料覆盖区间（… → …）内没有事件」

**为什么**：这只股票在那个窗口里确实没有事件。语料是全市场的，但**不是每只票每天都有事**。

**怎么办**：换标的、放宽区间，或换 `ma_cross`。事件表那块也会写清这次的语料覆盖区间，对着看就知道了。

### B3. 报 503：「本地数据未就绪」/「行情数据尚未落盘」

**为什么**：这台服务的数据还没下载或落盘。行情与事件都是**先落盘才能查**的。

**怎么办**：找部署这套服务的人跑一次数据下载（自建部署见 README 的「数据来源与复现边界」）。**这不是你的操作问题。**

### B4. 指标卡上「年化」「夏普」显示 `—`，或提示「样本仅 N 个交易日」

**为什么**：样本太少，这两个指标算不出来（标准差为 0）或没有意义。

**怎么办**：把区间拉长。提示原文会告诉你放大了多少倍噪声——**短窗口的年化不要当结论用**。

### B5. 同一只票、同一个策略，我跑出来的数字和教程不一样

**为什么**：**数据是滚动的**。行情止于导入当天，事件语料随日增量前移；不同的数据末端跑出来的净值当然不同。

**怎么办**：教程里每一个数都标了数据边界（行情末端、语料窗口），对上那个边界再比。**结构与读法不变，数字会变**——这是设计如此，不是 bug。

### B6. 「未成交信号」里有一堆单子，是策略坏了吗

**为什么**：不是。这是 **A 股规则**在如实记账：一字涨停你买不进、一字跌停你卖不出、停牌就是不能撮合。

**怎么办**：不用管它，这是**真实交易里也会发生的事**。每一条都带原因（`一字涨停` / `停牌` / `资金不足以买入一手`）。如果数量特别多，说明你的策略总在涨停板上追高——那是策略问题，不是引擎问题。

## C. 策略工作台

### C1. 检查结果里出现 `✕ R1` / `✕ R2` / `✕ R3`，点「保存并运行」被拦

**为什么**：R0–R5 是**前视静态检查**，只读地分析你的源码（不执行）。**error 档会拦住运行**，warning 档只提示。

**怎么办**：点那条 finding，编辑器会跳到对应行。常见几条的原文与出路：

| 码 | 提示大意 | 出路 |
|---|---|---|
| R1 | `不允许 import duckdb：…行情与事件数据只能经 ctx 取` | 数据从 `ctx` 拿，不要自己连数据源 |
| R2 | `.shift(-1) 会取到未来 1 根 bar` | 往回看用负偏移（`[-2]` 是前一根） |
| R3 | `ctx.history[ctx.index + 1] 越过当前 bar` | 想取当前 bar 用 `[-1]`；比较相邻两根用 `zip(closes, closes[1:])` |

### C2. 为什么没有 pandas？

**为什么**：**这是故意的**。`shift(-1)`、`bfill()` 正是前视泄漏最常见的来源；不给 pandas，就从工具层面关掉了这条路。策略是纯计算，只开放 `math` / `statistics` / `itertools` / `functools` / `collections` / `dataclasses` / `typing` / `datetime`。

**怎么办**：模板里的五个策略（含 RSI、唐奇安）全是纯 Python 写的，照着写就行。需要滚动均值就自己算——**能算出来的都算得出来，只是不给那条捷径**。

### C3. 提示「策略执行超过墙钟上限 20s，已终止」

**为什么**：策略跑在沙箱子进程里，有三层配额：CPU 15s / 内存 1GB / 墙钟 20s，另外还有输出上限。

**怎么办**：八成是死循环。检查循环的退出条件；如果确实是计算量大，缩小回测区间。

### C4. 提示「策略的 stdout 输出超过 … 字节上限」

**提示原文还有半句**：`stdout 是沙箱协议通道，调试信息请用 print——它默认走 stderr`。

**怎么办**：把 `print` 当调试用是**可以的**（它走 stderr）；但**不要往 stdout 写东西**——那是沙箱回传结果的通道，写满了就废了。

### C5. 我改了策略代码，之前那次回测还能复现吗

**为什么**：每次运行都记录**当次源码的哈希**。

**怎么办**：能。回测页会如实标注状态：`代码与当次一致` / `已非当次运行的代码` / `策略已删除`。看到「已非当次运行的代码」就说明你现在看到的源码不是那次跑的那份——报告本身没有变。

## D. 模拟盘

### D1. 我点了「批准」，为什么没有成交？

**为什么**：**批准 ≠ 成交**。批准只改状态；成交发生在**下一交易日的开盘**——批的那一刻，成交价还不存在。

**怎么办**：再点一次**「推进一天」**。成交后卡片上会多一行「实际成交 N 股 @ 价格」。

### D2. 报 422：「每只标的的配额买不起一手：600519（配额 250,000 元 < 一手 25,000 元）；…——把初始资金调大，或把池子缩小」

**为什么**：池子里每只标的拿**等额额度**（初始资金 ÷ 只数），A 股最小交易单位是 **100 股（一手）**。

**怎么办**：按提示算——初始资金至少要 `标的价格 × 100 × 池子只数`。把资金调大，或把池子缩小。

### D3. 报 422：「区间内有 N 个交易日，超过上限 250——拆分区间」

**为什么**：单次会话最多 250 个交易日（约一年）。

**怎么办**：拆成几段跑。另外区间**至少要有 2 个交易日**（T 日生成决策、T+1 开盘成交）。

### D4. 报 422：「区间终点 … 晚于本地行情最后一根 bar（…）——模拟盘只能回放已经发生的日子」

**为什么**：模拟盘是**回放式**的，只能重演已经发生的行情。行情止于导入当天。

**怎么办**：把终点改早，或留空（用本地行情末端）。**这是模拟盘不是实时盘**——想跟真实日历滚，要等下一阶段。

### D5. 决策变成「已批准未成交」，为什么？

**为什么**：批准不等于一定能成交——一字涨停买不进、停牌不能撮合、资金不足买不起一手。

**怎么办**：看卡片上的「未成交原因」。这是**如实记账**：真实交易里也会发生。

### D6. 推进时提示「会话已被推进过（并发）——刷新后再看」

**为什么**：同一个会话在两个标签页里同时推进了。

**怎么办**：刷新。**同一会话的操作是串行的**，不会算错账，只会告诉你这次没生效。

## E. 研报与导出

### E1. 「出研报」点下去，提示「这批数据已有报告，打开的就是那一份（未重算、未再调用模型）」

**为什么**：**这是对的**。同一批数据（同一账户同一状态）已有报告时**不重算**——报告是确定性的，重算只会烧钱。

**怎么办**：直接看那一份。想要一份新的，先推进会话让账户状态变化。

### E2. 导出 PDF 和「打印」有什么区别？

**怎么办**：

- **导出 PDF**：**服务端渲染**，与屏幕逐像素同款，**不弹打印对话框**，直接下载。推荐用这个。
- **打印**：走浏览器打印对话框（可以自己选纸张、边距）。
- **导出 Markdown**：要拿去二次编辑时用。

### E3. 分享链接发给别人，对方打不开 / 提示「分享链接已失效」

**为什么**：分享**被撤销了**，或者链接不完整。撤销之后**旧链接立刻失效**，这是设计如此。

**怎么办**：让分享者重新「生成分享链接」。注意：**撤销分享不可逆**，只能重新生成一个新链接（旧链接不会恢复）。

### E4. 研报里写着「N 条证据在本地语料里查无此行（如实留空，未编造）」

**为什么**：报告里的证据要能在本地事件语料里对得上。对不上的会**如实标注**，而不是悄悄删掉或补一条假的。

**怎么办**：不用处理。这恰恰是这套系统**不编数据**的证据——看到这条说明闸门在工作。

## F. 深度研究

### F1. 第一次提问要等很久

**为什么**：**冷启动**。本地检索模型（嵌入 + 精排）首次加载要十几秒，之后每次调用就快了。

**怎么办**：等第一次跑完，同一个进程里的后续提问会明显变快。已知边界写在 PRD 里：**冷启动首问 ≤ 60s、预热 ≤ 30s**，不假装更快。

### F2. 出现了「措辞需要你确认」/「预算已到上限」的卡，卡住不动了

**为什么**：这是**人工审批闸门**，不是报错。两类情况会停下来等你：正文出现了绝对化表述或买卖指令；token / 时间 / 成本任一超限。

**怎么办**：选一个继续——「继续」/「放弃这段」，或「加预算继续」/「用现有结果收尾」。可以留一句备注。**断线也不怕**：重新进运行页，这张卡还在（状态从服务端恢复）。

### F3. 运行状态显示「已完成（有降级）」，是什么意思

**为什么**：某个取证角色没跑出来（数据源不可用、该时点没有材料、解读超时），系统**降级而不是崩溃**——缺什么如实说，报告照样出。

**怎么办**：看报告里的「如实标注：本次的缺口」一块，逐条写着哪个角色缺了什么。

## G. 数据与口径

### G1. 事件语料的窗口为什么这么短？

**为什么**：数据源的**保留期是滚动的**：新闻 **3 个月**、公告 **24 个月**。超期的**永久不可得**，平台声明不补采。

**怎么办**：接受这个边界，或者自建部署后长期积累（本地语料只增不减，但起点是固定的）。启动时会自动补缺口，但**断供超过 3 个月那段就永久拿不到了**。

### G2. 为什么基准不是沪深 300？

**为什么**：数据源**不覆盖指数行情**。与其编一个假的指数，不如如实用一个代理：**全市场等权组合**（日频再平衡，剔除新股首日与复牌样本）。

**怎么办**：直接用，报告里每一步都自述了这一点。**不要把这里的"基准"当成大盘涨跌**。

### G3. 本地行情覆盖哪些标的？

**怎么办**：全市场 A 股日线，**2020-01-02 起**。查不到一般是代码写错了（要六位数字），或者该标的还没上市 / 已经退市。对话里问行情时，工具会明确回一句「本地行情库没有 XXXXXX 的数据」并给出示例格式。

### G4. 图上没有线 / 表格是空的

**怎么办**：按顺序排一遍——

1. **区间里确实没有数据**（比如事件驱动跑了语料窗口之外）→ 换个区间
2. **换了口径但没重跑**（比如因子页从「毛」切到「净」，而这次请求关了费用）→ 页面会直接告诉你：`本次请求关闭了费用，只有毛曲线——净曲线要重跑一次并打开费用。`
3. **就是没有符合条件的数据**→ 空态会写明原因（例：`本窗口没有有效信号日——池子不足或行情末端之后没有前向收益，如实留空。`）——**空就是空**，不是渲染坏了

### G5. 页面上的 `—` 是什么意思？

**答案**：**没有数据**。本项目的一致口径是**不补零**——「没有数据」和「数据是 0」是两回事，补零会让两者混淆。

## H. 部署与运行（自建部署时看）

### H1. 前端一直显示「连接失败，请确认后端已启动」

**怎么办**：后端没起来，或起来但不在 `8000`。先 `curl http://127.0.0.1:8000/health`，返回 `{"status":"ok",...}` 才算好。

### H2. `pnpm build` 报错 / 页面 500

**怎么办**：**先停掉 dev server 再 build**（同一端口写 `.next/` 会打架）。这是操作顺序问题，不是代码问题。

### H3. Docker 的 Postgres 起不来

**怎么办**：检查 **5433** 端口是否被占（我们用 5433 而不是 5432，就是为了避开本机已有的 Postgres）。另外 `postgres:18` 的数据卷路径改过——用旧写法会让数据落进匿名卷，`docker compose down -v` 即丢库，详见 README。

### H4. `.env.example` 里又多了几个变量，我的 `.env` 要不要跟着同步？

**为什么**：这两个文件是**两个角色**——`.env.example` 是**给人看的清单**（进 Git，列出所有旋钮与说明），程序运行时**不读它**；程序读的是 `.env`。而 `config.py` 里每个设置都带默认值，所以 `.env` 少几个键**不会出错**，只是那几项走默认。我们核对过：模板里有、而你的 `.env` 里没有的那些键，**代码默认与模板写的逐字一致**——这就是「少 17 个键却一切正常」的原因，不是侥幸。

**怎么办**：**通常不用管**。只有当你确实想**改某个行为**时，才往 `.env` 里加那一行——比如想打开数据层缓存就加 `CACHE_ENABLED=true`（`.env` 的优先级高于代码默认；改完重启后端生效）。反过来，往 `.env.example` 里改**不改变任何行为**，那是在改文档，不是改配置。
